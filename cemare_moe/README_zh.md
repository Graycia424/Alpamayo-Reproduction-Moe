# Alpamayo-1.5-Local (VLA模型端到端自动驾驶本地复现与评测系统)

本项目是基于 NVIDIA Alpamayo-1.5 的视觉-语言-动作 (Vision-Language-Action, VLA) 端到端自动驾驶模型的本地离线复现版本。该项目作为我在实习期间的核心工作之一，**特别包含了针对多摄像头配置的消融实验**，旨在解决原版模型对云端依赖的问题，并通过系统化的摄像头组合消融研究，验证不同视角对轨迹预测精度的贡献。实现了从多模态数据集处理、端到端推理、轨迹评测到 BEV (鸟瞰图) 可视化的全链路本地化。

## 🌟 核心工作与贡献 (Internship Highlights)

*   **本地化离线推理架构部署**：成功将 Alpamayo-1.5 10B 级 VLA 大模型及其依赖的数据管道（如 PhysicalAI 自动驾驶数据集）剥离重构，实现了完全本地和离线环境下的端到端推理运行。
*   **多摄像头消融实验（核心研究）**：
    *   通过不同摄像头配置组合（1路、2路、4路、全景7路等）的系统化运行，评估各个视角对轨迹预测精度的贡献度。
    *   **消融研究方法**：固定模型权重，仅改变摄像头输入参数，通过 ADE 指标对比分析各摄像头的重要性。
    *   **研究成果**：量化了单个摄像头的贡献、多摄像头融合的边际收益、以及成本与精度的权衡。
    *   支持动态配置多摄像头视角，并结合车辆自车运动历史信息 (Egomotion) 与文本导航指令进行融合评估。
*   **端到端轨迹预测与评测框架**：
    *   构建了完整的推理脚本 (`inference_ade.py`, `inference_vitz.py` 等)。
    *   实现了预测轨迹与真实轨迹的对比功能，并引入了严谨的 **minADE_6** (最小平均位移误差) 指标进行模型预测精度的量化评估。
    *   引入了语言指令条件注入，评估模型对正常指令与反事实（Swapped）指令的服从能力。
*   **BEV 轨迹可视化引擎**：开发了一套基于 matplotlib 的鸟瞰图可视化验证工具，支持将多相机的原始视野图像、预测生成的6模态轨迹集、GT 历史路线和指令级对比轨迹叠加映射至 BEV 平面，为模型调试与结果展示提供了极为直观的支持。
*   **未来扩展预留平台**：在基础代码上，预留并准备支持诸如模型微调（Fine-tuning）、RL 强化微调以及一致性训练等进阶方向。

## 🛠 系统组成 (Project Structure)

本项目是 **Alpamayo-1.5 的多摄像头消融实验评估系统**，通过不同相机配置的组合和运行，分析各摄像头对轨迹预测精度的贡献。

核心代码模块分布：
- `alpamayo1_5/`：存放模型定义、处理器（Processor）、坐标系转换与几何辅助工具等核心推理依赖。
- `dataset.py` / `load_physical_aiavdataset.py`：负责解析与加载自动驾驶 PhysicalAI 多模态离线数据集。
- `inference_ade.py`：**主要入口文件**。进行端到端预测、生成轨迹、计算 ADE 指标并调用 BEV 可视化工具。
- `run_multiple_clips.py` / `launch_parallel.py`：支持批量并行处理多段短视频（Clips）的测试流水线。
- `viz_utils.py`：BEV 轨迹渲染、多镜头网格拼接拼图的代码实现。

## 🔬 多摄像头消融实验详细结果 (Ablation Experiment Results)

本实验基于 **Alpamayo-1.5 的抽样 10 个 chunk，共 1000 个 clips**，通过固定模型权重、仅改变摄像头输入配置的方式，系统化地评估各摄像头对轨迹预测精度的贡献。

### 实验设置与标签定义

场景标签直接读取数据集中自车未来的真实物理轨迹（Ground Truth），通过判断车辆在最后时刻的横向（Y轴）偏移量是否超过 2.5 米，来自动判定该场景是直行、左转还是右转。*（注：可能存在边界误差）*

### 核心实验发现

![摄像头MoE消融实验总体结果](../images/cemare_moe/ablation_overview.png)

#### 1️⃣ **4摄像头最优方案**
- **4cam baseline（front-wide + front-tele + cross-left + cross-right）**
- **minADE：0.927m** ✓ 最优组合
- 包含前向广角、前向长焦、左侧、右侧视角
- 为轨迹预测任务的黄金配置

#### 2️⃣ **摄像头数量与性能关系**

![各场景 minADE 对比](../images/cemare_moe/scene_minADE_comparison.png)

- **1摄像头 → 4摄像头**：性能持续提升
- 说明**前向视角和侧向视角对规划任务各有不可替代的贡献**
- 多摄像头融合有显著协同效果

#### 3️⃣ **后视替换方案评估**
三种后视替换方案总体均显著劣于 4cam baseline：

| 方案 | 替换策略 | minADE | 评价 |
|-----|---------|--------|------|
| **4rt** | 用后视替换 front-tele | 2.707m | 严重劣化（唯一低于1摄像头下界） |
| **4rl** | 用左后视替换 cross-left | 性能下降 | 保留部分有效信息 |
| **4rr** | 用右后视替换 cross-right | 性能下降 | 保留部分有效信息 |

**结论**：用后视替换 front-tele 会**大幅损失性能**，但并非完全无效——4rl 和 4rr 仍保留了部分有效信息，只是远不及 front-tele 对规划任务的贡献。

#### 4️⃣ **全景7摄像头反向发现**

![高误差 clip 占比分析](../images/cemare_moe/high_error_rate.png)

- **增加全部 7 个摄像头反而使性能下降至 1.376m**
- 表明**后视信息对前向规划任务是噪声**
- 相比 4cam baseline（0.927m）性能下降 48.3%

**关键洞察**：
```
不同摄像头承担的功能不同 → 差异化摄像头处理结构的设计基础

✓ front-wide + front-tele：前向主视角（精细化观察）
✓ cross-left + cross-right：侧向辅助视角（场景理解）
✗ rear cameras：噪声信息（对前向规划无实际贡献）
```

### 消融实验总体结论

| 维度 | 发现 | 启示 |
|-----|------|------|
| **最优配置** | 4cam (0.927m) | 成本-性能最优点 |
| **融合优势** | 前+侧视角的协同效应 | 多摄像头设计的必要性 |
| **边际收益** | 添加更多摄像头递减 | 存在最优配置上界 |
| **噪声问题** | 后视信息产生干扰 | 需要**差异化处理策略** |

## 🎯 研究成果与部署建议

### 实际应用启示

![BEV轨迹对比示例](../images/cemare_moe/camera_bev_example.png)

1. **摄像头选型**：优先配置前向双目（广角+长焦）+左右侧向三路，避免后视多路冗余
2. **架构设计**：为不同视角设计**差异化的特征提取与融合模块**，而非通用处理
3. **成本优化**：在满足精度要求（~0.95m minADE）前提下，4摄像头为最优成本点
4. **模型改进**：后续可探索**自适应摄像头权重学习**，动态调整各视角的贡献度

## �🚀 快速上手 (Quick Start)

### 1. 环境依赖 (Environment Setup)

推荐使用 conda 配置：
```bash
# 推荐环境
python == 3.12
cuda基础环境支持 (如 cuda 12.1)
```

克隆本仓库并在本地执行：
```bash
git clone https://github.com/IP127000/Alpamayo-VLA-Local.git
cd Alpamayo-VLA-Local
pip install -r requirements.txt
```

### 2. 数据集说明
您无需下载完整的 [NVIDIA PhysicalAI 自动驾驶数据集](https://huggingface.co/datasets/nvidia/PhysicalAI-Autonomous-Vehicles)，为了运行测试，只需确保本地存有若干片段（Clips）及其对应的传感器内外参 Parquet 文件即可。

### 3. 本地推理与评测运算
可以使用提供的评估脚本执行单片段的推理与可视化：
```bash
python inference_ade.py \
    --clip-id 275e7810-408a-43c7-84c0-f83dbf102268 \
    --cameras-config 4_cam \
    --visualize 
```
运行完成后，终端会打印出生成的多模态文本及 `minADE_6` 的误差结果，并在根目录生成一张由多相机画面和 BEV 对比轨迹拼合的解析图 (`bev_trajectory.png`)。

## 📌 项目关系说明 (Project Relationship)

**Alpamayo-Reproduction-Moe 包含两个独立的研究方向**：

| 项目 | 基础模型 | 研究内容 | 文件位置 | 研究阶段 |
|-----|---------|---------|---------|---------|
| **轨迹 MoE** | R1 | Decoder 层 MoE 架构设计 | `trajectory_moe/` | 架构创新 |

本项目 (`cemare_moe/`) 是**Alpamayo-1.5 的多摄像头消融实验系统**，通过不同摄像头参数组合的运行和 ADE 指标对比，量化各个摄像头对轨迹预测精度的贡献，为实际部署提供数据支持。
